# Документация проекта

**Директория:** `doc/`

Здесь находятся историческое ТЗ, requirements/test cases и изображения, использованные первоначальной технической
документацией.

## Файлы

### `TESO Fisher.docx`

Исходная версия технического задания в Word.

### `TESO Fisher.pyns`

Схема/описание проектной документации в формате, который использовался в исходном процессе документирования.

### `TESO_Fisher_luaParser.pyns`

Отдельная проектная документация по Lua parser.

### `requirements.csv`

32 строки требований: основной roadmap проекта.

Требования сгруппированы в три больших блока:

- `010000` — навигация к лунке;
- `020000` — определение состояния лунки;
- `030000` — автоматическая рыбалка.

### `test_cases.csv`

Историческая тестовая спецификация. Не считать этот файл источником текущего состояния тестов: реальные pytest-тесты
находятся в `tests/`.

### `README_SPECIFICATION.md`

Копия старого корневого README, сохранённая перед обновлением текущего корневого README. Это полезный источник
первоначального замысла и терминологии.

## Как читать старое ТЗ

Старое ТЗ описывает **целевую систему**, а не только текущую реализацию. Нереализованные требования не являются ошибкой
проекта сами по себе — это запланированные этапы.

## `images/`

Скриншоты и иллюстрации для исторической документации. Подробнее см. `doc/images/README.md`.
